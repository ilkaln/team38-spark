# Apache Spark on YARN

1. Описание проекта

Проект предназначен для выполнения учебных заданий по Apache Spark на существующем Hadoop-кластере.

Spark запускается под управлением YARN, а для доступа к распределённому хранилищу используется HDFS.

На текущем этапе реализованы запуск и проверка SparkSession. Подключение к HDFS, чтение данных и их преобразование будут добавлены отдельными этапами.

2. Структура проекта

team38-spark/
├── README.md
├── src/
│   ├── spark_session.py
│   └── start_spark_session.py
└── scripts/
    ├── setup_spark.sh
    ├── spark_env.sh
    ├── run_spark.sh
    └── check_yarn.sh

Python-файлы

src/spark_session.py — общие функции создания и остановки SparkSession. Вынесение этих операций в отдельный модуль позволяет повторно использовать их в других этапах проекта.

src/start_spark_session.py — создаёт SparkSession, выводит версию Spark, используемый мастер и идентификатор приложения, после чего завершает сессию.

Bash-скрипты

scripts/setup_spark.sh — загружает, проверяет контрольную сумму и устанавливает Apache Spark.

scripts/spark_env.sh — задаёт переменные окружения для Spark, Hadoop и YARN.

scripts/run_spark.sh — загружает настройки окружения и запускает указанное Python-приложение с помощью spark-submit под управлением YARN.

scripts/check_yarn.sh — выводит список приложений YARN и их состояния.

3. Требования

Linux и Bash.

Java 17.

Установленный клиент Hadoop.

Доступ к существующему кластеру HDFS и YARN.

Настроенные конфигурационные файлы Hadoop.

## Установка Spark

Для установки используется Apache Spark 3.5.3 без встроенных Hadoop-библиотек. Это позволяет использовать библиотеки Hadoop, доступные в окружении кластера.

Перейдите в каталог проекта:

```bash
cd ~/spark
```

Запустите установочный скрипт:

```bash
chmod +x scripts/setup_spark.sh
./scripts/setup_spark.sh
```

Скрипт скачивает архив Spark, проверяет его контрольную сумму, распаковывает файлы в каталог `$HOME/opt` и удаляет скачанные архивы.

После установки Spark находится по пути:

```text
$HOME/opt/spark-3.5.3-bin-without-hadoop
```

Установку достаточно выполнить один раз для данного пользователя и машины.

## Настройка окружения

После установки необходимо загрузить переменные окружения. Для этого используется отдельный файл `scripts/spark_env.sh`.

Выполните команду из корня проекта:

```bash
source scripts/spark_env.sh
```

Файл задаёт следующие переменные:

- `SPARK_HOME` — путь к установленному Spark.
- `PATH` — добавляет каталог с исполняемыми файлами Spark.
- `HADOOP_CONF_DIR` — путь к конфигурации Hadoop.
- `YARN_CONF_DIR` — путь к конфигурации YARN.
- `SPARK_DIST_CLASSPATH` — classpath с библиотеками Hadoop, полученный через `hadoop classpath`.

**Важно:** файл необходимо подключать через `source`, а не запускать как отдельный скрипт. Переменные будут доступны в текущем терминале.

При открытии нового SSH-сеанса настройку необходимо повторить. При желании её можно подключить автоматически через `~/.bashrc`.

### Проверка установки

После загрузки переменных выполните:

```bash
spark-submit --version
```

Команда должна вывести версию Spark и используемую версию Java.


## Запуск SparkSession под YARN

Запуск приложения

Из корневого каталога проекта выполнить:

```bash
chmod +x scripts/run_session.sh scripts/check_yarn.sh
./scripts/run_session.sh "$PWD/src/start_spark_session.py"
```

Скрипт `run_spark.sh` передаёт приложению параметры:

--master yarn — использование YARN для управления ресурсами;

--deploy-mode client — выполнение управляющего процесса приложения в клиентском терминале.

Python-программа создаёт SparkSession с помощью SparkSession.builder и getOrCreate().

Проверка результата

При успешном запуске в терминале выводятся:

версия Spark;

используемый мастер;

идентификатор приложения YARN.

В качестве мастера ожидается yarn.

Проверить состояние приложения в YARN можно отдельной командой:

```bash
./scripts/check_yarn.sh
```

После завершения Python-программы приложение может находиться в состоянии FINISHED. Это ожидаемое поведение: на первом этапе мы проверяем запуск сессии, а не запускаем постоянно работающий сервис.
